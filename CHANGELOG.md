# Changelog

## 2.12.0 — 2026-10-27

Видео с YouTube больше не зависают на «55% Обзваниваю стриминги».

- Если Telegram не принимает карточку из-за превью (плеера YouTube или
  картинки по ссылке), бот отправляет ту же карточку без превью, а не
  теряет её. Причина отказа пишется в лог.
- Если поиск по ссылке всё-таки сломался, бот больше не молчит с вечным
  прогрессом. Он пишет «⚠️ Не получилось собрать пост» с кнопкой
  «Повторить». `/status` теперь показывает не только тип последней
  ошибки, но и что ответил Telegram.
- YouTube снова оформляется как до 2.11.0. Если в подборке клипов
  скачался только один кадр, он становится обычной квадратной обложкой с
  подписью, без широкого кадра. Широкий кадр остался только у фильмов и
  сериалов.
- Сообщения об ошибках больше не начинаются с двух эмодзи подряд
  («⚠️ 🔎 Релиз не найден» → «🔎 Релиз не найден»).
- Чистка: у внутренней отправки публикации убран неиспользуемый параметр
  `channel_style`.

## 2.11.2 — 2026-10-26

Рефакторинг и полная проверка кода, поведение бота не меняется.

- Отправка карточек: видео, радио, плейлисты и артисты шли через четыре
  почти одинаковые функции по 70–90 строк. Теперь это одна общая функция
  и таблица с тем, чем эти виды отличаются: клавиатура, текст, коллаж.
- Пакетный поиск ссылок: одна попытка запроса к сервису и разбор её
  результата («нашёлся», «нет такого релиза», «сервис лежит, повторить»)
  вынесены в отдельные функции. Сложность главной функции упала с 30 до
  17. Ветка «Song.link не нашёл релиз» раньше не была покрыта тестами,
  теперь покрыта вместе с повторами и SoundCloud.
- Чистка по линтеру: `asyncio.TimeoutError` → `TimeoutError`, импорты из
  `collections.abc`, неиспользуемые параметры и переменные убраны.
- Проверено: 1263 теста, покрытие 85.65%, mypy, ruff, bandit, аудит
  зависимостей чистый.

## 2.11.0 — 2026-10-26

Кадры фильмов и сериалов с подписью канала.

- Карточки Netflix, Apple TV+ и Disney+ показывают кадр с подписью канала,
  как обложки релизов. Кадр не обрезается в квадрат: он остаётся широким,
  16:9, с той же тёмной плашкой и подписью внизу. В inline-режиме кадр
  ещё и виден в списке результатов. Без брендинга
  (`BRAND_PHOTO_FRAME=0`) или если кадр не скачался, показывается
  исходная картинка сервиса.
- Если в подборке клипов из двух кадров скачался только один, он остаётся
  широким кадром со значком ▶, а не квадратной обрезкой.
- Disney+: на региональных ссылках (`/en-gb/`, `/de-de/`…) название
  больше не превращается в «Watch Moana» или «Vaiana ansehen». Оно
  берётся из блока данных страницы, поэтому трейлер и саундтрек тоже
  ищутся по настоящему названию.

## 2.10.0 — 2026-10-21

Три улучшения интерфейса по макету.

- «✕ Отмена» прямо в подсказке ввода. Раньше «пришли текст» можно было
  отменить только командой `/cancel`; теперь в одном сообщении и поле ответа,
  и кнопка (Bot API 10.3). Отмена убирает только подсказку — карточка
  остаётся.
- Длинная цитата сворачивается. Свой текст длиннее ~5 строк на телефоне
  показывается первыми строками с «показать полностью» от Telegram; жирный,
  курсив и ссылки сохраняются. Короткая цитата — как раньше.
- «🎧 Саундтрек» в карточке фильма или сериала открывает карточку альбома
  прямо в боте (`t.me/StonerHandBot?start=sound_…`) — её можно изменить и
  опубликовать. Без имени бота остаётся ссылка на album.link.
- Команда вида «/start …» больше никогда не становится подписью к посту.

## 2.8.0 — 2026-10-21

Ресерч, безопасность и исправления.

- Безопасность: Pillow 12.3.0 → 13.0.0. В 12.3.0 восемь опубликованных
  уязвимостей (переполнения буфера в JPEG/TIFF, обход защиты от
  «декомпрессионных бомб»), а бот обрабатывает чужие картинки — обложки и
  загруженные файлы. Коллаж и подпись обложки проверены на новой версии.
- Python 3.11+: Pillow 13 не поддерживает Python 3.10, у которого в этом
  месяце закончилась поддержка. CI проверяет 3.11–3.14, `tomli` больше не
  нужен.
- Исправлено: `/cancel` во время ввода текста удалял не только подсказку
  «пришли текст», но и саму карточку черновика (или экран подборки).
  Теперь уходит только подсказка.
- Исправлено: если все ссылки недоступны, бот всегда писал «Song.link не
  отвечает» — даже когда падал Netflix, YouTube или NTS. Теперь называется
  настоящий сервис, а при нескольких разных — общий текст без внутренних
  имён.
- Исправлено: Netflix, отказавший в доступе (403, таймаут), давал ложное
  «Релиз не найден». Теперь — «Сервис Netflix временно не отвечает» с
  кнопкой «Повторить»; несуществующий тайтл по-прежнему «не найден».
- Время публикации: все формы («21:00», «25.10 19:30», «завтра 18:30»)
  читаются в часовом поясе бота одинаково; понимается и ISO-формат
  «2026-10-25 19:00».
- Мониторинг: живая проверка карточек на GitHub три дня падала из-за
  устаревшего аргумента в самом скрипте проверки. Исправлено, скрипты
  проверок добавлены в mypy (он ловит такие ошибки до мержа), Netflix
  добавлен в проверку карточек, а упавшая проверка теперь сама открывает
  issue и закрывает его после восстановления.
- Рефакторинг: один `send_json` для шести эндпоинтов вместо шести копий,
  удалён неиспользуемый код.
- Проверено и актуально: Telegram Bot API 10.3 (последняя),
  python-telegram-bot 22.8, httpx 0.28.1; аудит зависимостей чистый.
- Тесты: +12 (полный запрос к `/api/set_webhook`, `/cancel`, экран удаления
  данных, тексты ошибок провайдеров, сбой Netflix, часовой пояс).
