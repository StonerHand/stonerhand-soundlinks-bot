# Проверка релиза StonerHandBot

Автотесты проверяют данные, лимиты, кнопки и fallback. Этот короткий список
закрывает то, что можно проверить только настоящими клиентами Telegram.

## Перед production

- [ ] CI зелёный, preview-деплой отвечает, `/api/health` возвращает `ok: true`.
- [ ] `/api/collage?health=1` возвращает JSON с layout `2`, `3` и `4`.
- [ ] `/api/smoke` возвращает `ok: true`, все семь сценариев имеют `ok: true`.
- [ ] Версия в `pyproject.toml`, пакете и `CHANGELOG.md` совпадает.
- [ ] В репозитории нет `.env`, токенов, временных файлов и удалённых компонентов.
- [ ] В GitHub Actions настроены `VERCEL_TOKEN`, `VERCEL_ORG_ID` и
      `VERCEL_PROJECT_ID` для защищённого автоматического отката.

## Telegram iOS и Android

- [ ] `/start`: один компактный экран, главная кнопка «Создать пост» видна сразу.
- [ ] «••• Ещё»: открываются помощь, сервисы, каналы, пример и приватность.
- [ ] Один Spotify/Apple Music/YouTube URL: есть обложка, артист, название,
      кнопка исходной площадки и отдельная кнопка «Все платформы».
- [ ] В названии Spotify-релиза нет `Album by …`, `song and lyrics by …` и
      хвоста `| Spotify`, включая карточку из сохранённого черновика.
- [ ] URL музыкального источника не повторяется в подводке — ни открытым
      текстом, ни скрытой гиперссылкой; обычная внешняя ссылка сохраняется.
- [ ] SoundCloud-only релиз не получает Spotify-кнопку; ни одна кнопка площадки
      не ведёт на страницу поиска вместо прямого релиза.
- [ ] Поиск `артист — трек`: выбор результата понятен, «Изменить запрос» работает.
- [ ] 3–10 ссылок: порядок сохранён, каждая ссылка имеет статус, дубли объединены.
- [ ] Во время поиска работает «Отменить поиск», новый запрос не создаёт дубль.
- [ ] «Изменить»: все экраны возвращаются назад, подписи не обрезаны.
- [ ] «Без хэштегов»: теги отсутствуют в preview, отправке себе, канале и очереди.
- [ ] Автохэштеги: нет неподтверждённого жанра (например, `#rnb` у Knocked Loose).
- [ ] «Поделиться»: обложка и кнопки сохраняются; Classic fallback выглядит полноценно.
- [ ] 2–4 разных релиза: Classic показывает коллаж; неполная подборка — одну обложку.
- [ ] Подборка: добавление, порядок, удаление, отмена удаления и очистка работают.
- [ ] Светлая и тёмная темы: текст, опасные и основные кнопки читаемы.
- [ ] `primary`, `success` и `danger` выглядят одинаково понятно на iOS и
      Android; neutral-кнопки не перетягивают внимание.
- [ ] `/privacy`: показано предупреждение; тестовое удаление очищает историю и подборку.

## Telegram Desktop и Web

- [ ] Карточка не распадается при широкой колонке; длинные названия сокращаются корректно.
- [ ] URL-кнопки открывают разные целевые сервисы, «Все платформы» ведёт на Songlink/Odesli.
- [ ] Inline-запрос `@StonerHandBot артист — трек` отправляет карточку с обложкой.
- [ ] Повторный быстрый клик не публикует и не отправляет пост дважды.

## Администратор

- [ ] `/status`: Telegram, webhook, Redis, очередь и площадки без критических ошибок.
- [ ] `/stats`: видны анонимная воронка, rate limit и fallback-метрики.
- [ ] Тестовая публикация в канал и отложенная публикация проходят ровно один раз.
- [ ] После merge production canary подтверждает точный commit.
- [ ] Тест rollback guard отклоняет здоровый, нечитаемый и не совпавший по commit deploy.

## Аварийный режим

Если ломается только генерация коллажей, установить
`COLLECTION_COLLAGE_ENABLED=0`. Если новый Telegram UI нестабилен, установить
`BOT_SAFE_MODE=1`: Rich Messages, Rich drafts, inline Rich media,
ephemeral-ответы и коллажи отключатся, а классические карточки останутся рабочими.
Для возврата установить переключатель в `1`/`0` и перед повторным включением
проверить `/status` и production canary.
