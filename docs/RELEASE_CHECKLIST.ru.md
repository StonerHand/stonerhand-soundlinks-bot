# Проверка релиза StonerHandBot

[← Документация](README.md) · [Запуск](SETUP.ru.md)

Автотесты проверяют данные, лимиты, кнопки и fallback. Этот короткий список
закрывает то, что можно проверить только настоящими клиентами Telegram.

## Перед production

- [ ] CI зелёный, preview-деплой отвечает, `/api/health` возвращает `ok: true`.
- [ ] `/api/collage?health=1` возвращает JSON с layout `2`, `3`, `4`, `5` и `6`.
- [ ] `/api/smoke` возвращает contract `6`: одиннадцать публикаций и десять UI/UX-экранов
      имеют `ok: true`.
- [ ] `provider-canary` зелёный: живые Spotify, Deezer/MusicBrainz, SoundCloud,
      YouTube, Apple Music и NTS возвращают полные и не рекламные метаданные.
- [ ] Версия в `pyproject.toml`, пакете и `CHANGELOG.md` совпадает.
- [ ] Wheel собран и проверен через `tests/check_distribution.py`; исходный архив
      содержит API, тестовые данные, документацию и пример настроек.
- [ ] В репозитории нет `.env`, токенов, временных файлов и удалённых компонентов.
- [ ] В GitHub Actions настроены `VERCEL_TOKEN`, `VERCEL_ORG_ID` и
      `VERCEL_PROJECT_ID` для защищённого автоматического отката.
- [ ] `CRON_SECRET` одинаков в Vercel и GitHub Actions; ручной запуск
      `queue-worker.yml` подтверждён, а health показывает свежий `last_tick_at`.
- [ ] Opt-in Telegram canary прошёл в отдельном закрытом чате и удалил Classic,
      Rich, collection и SoundCloud-only тестовые сообщения.

## Telegram iOS и Android

- [ ] `/start`: один компактный экран, «Создать пост» видно сразу;
      «Мои материалы» открывает подборку, черновики и историю.
- [ ] Первый личный `/start` показывает исходную аватарку один раз; повторный — сразу меню.
- [ ] До создания первой карточки доступно «Попробовать на примере», затем — полное меню.
- [ ] «Настройки»: сохраняются язык, оформление новых карточек и хэштеги; доступны помощь и приватность.
- [ ] Один Spotify/Apple Music/YouTube URL: есть обложка, артист, название;
      подтверждённая «Слушать трек / альбом…» идёт первой, а исходная площадка — следом.
      Apple-only fallback показывает только Apple и не обещает другие сервисы.
- [ ] Не найденный текстовый запрос повторяется на экране ошибки; доступны
      «Изменить запрос», «Отправить прямую ссылку» и возврат домой.
- [ ] В названии Spotify-релиза нет `Album by …`, `song and lyrics by …` и
      хвоста `| Spotify`, включая карточку из сохранённого черновика.
- [ ] URL музыкального источника не повторяется в подводке — ни открытым
      текстом, ни скрытой гиперссылкой; обычная внешняя ссылка сохраняется.
- [ ] SoundCloud-only релиз не получает Spotify-кнопку; ни одна кнопка площадки
      не ведёт на страницу поиска вместо прямого релиза.
- [ ] Поиск `артист — трек`: выбор результата понятен, «Изменить запрос» работает.
- [ ] Поиск `Deftones — Rickets` при недоступном Songlink создаёт карточку с
      обложкой, Apple Music, точной Spotify-ссылкой и `song.link/s/...`.
- [ ] 3–10 ссылок: порядок сохранён, каждая ссылка имеет статус, дубли объединены.
- [ ] Во время поиска работает «Отменить поиск», новый запрос не создаёт дубль.
- [ ] Текст и теги открываются прямо под постом; «Ещё» содержит редкие действия.
- [ ] Публикация показывает канал, отправку сейчас, планирование и отправку себе.
- [ ] Старые кнопки открывают рабочие экраны; возврат и отмена ввода сохраняют пост.
- [ ] Язык, новые посты и подборки разделены; правка черновика не меняет шаблон.
- [ ] Собственная обложка заменяется оригиналом/превью; отмена возвращает её.
- [ ] «Превью» присылает отдельный чистый пост без кнопок конструктора и не
      меняет открытую карточку.
- [ ] «Без хэштегов»: теги отсутствуют в preview, отправке себе, канале и очереди.
- [ ] Автохэштеги: нет неподтверждённого жанра (например, `#rnb` у Knocked Loose).
- [ ] Саундтрек Scott Pilgrim: название очищено от служебного хвоста, тип распознан;
      видео Deadyшки: канал показан источником, концертная версия сохранена.
- [ ] Подборка из десяти смешанных позиций сохраняет список, порядок и номера
      во всех трёх сетках; длинные заметки не вытесняют позиции.
- [ ] Переключатели тегов, свои теги и сохранение исправлений работают после
      перезапуска и изолированы между пользователями.
- [ ] Режим обложки, сетка и группировка сохраняются; YouTube остаётся с видеопревью.
- [ ] «Поделиться»: обложка и кнопки сохраняются; Classic fallback выглядит полноценно.
- [ ] 2–6 разных релизов: Classic показывает коллаж всех доступных разных
      обложек; при partial или одной обложке остаётся безопасный fallback.
- [ ] Текст над несколькими ссылками сохраняется перед подборкой и остаётся после
      «Поделиться»; сами музыкальные URL в подводке не повторяются.
- [ ] Подборка из 6 релизов уходит через «Поделиться» полностью;
      обрезанный список URL не создаёт частичный пост.
- [ ] Подборка: добавление, порядок, удаление, отмена удаления и очистка работают.
- [ ] Светлая и тёмная темы: текст, опасные и основные кнопки читаемы.
- [ ] `primary`, `success` и `danger` выглядят одинаково понятно на iOS и
      Android; neutral-кнопки не перетягивают внимание.
- [ ] При заданных `TELEGRAM_BUTTON_ICON_*_ID` custom emoji отображаются; без
      них подписи сохраняют понятные обычные иконки.
- [ ] `/privacy`: показано предупреждение; тестовое удаление очищает историю и подборку.

## Telegram Desktop и Web

- [ ] Карточка не распадается при широкой колонке; длинная подпись получает
      отдельный ряд. Проверено, как конкретный клиент обрезает очень длинные названия.
- [ ] URL-кнопки открывают разные целевые сервисы, «Слушать трек / альбом…» ведёт на Songlink/Odesli.
- [ ] Inline-запрос `@StonerHandBot артист — трек` отправляет карточку с обложкой.
- [ ] Пустой `@StonerHandBot` показывает до трёх недавних релизов или один пример.
- [ ] В `@BotFather` выполнен `/setinline`, placeholder:
      `Исполнитель — Название или ссылка`.
- [ ] Ошибка показывает одно уместное восстановление: изменить запрос,
      повторить, открыть поддерживаемые площадки или вернуться в подборку.
- [ ] После публикации редактор показывает канал, дату, «Открыть пост» и «Создать ещё».
- [ ] Изменение настройки, порядка и состава подборки подтверждается toast;
      доступная отмена действительно истекает через короткое время.
- [ ] Повторный быстрый клик не публикует и не отправляет пост дважды.

## Администратор

- [ ] `/status`: Telegram, webhook, Redis, очередь и площадки без критических ошибок.
- [ ] `/stats`: видны анонимная воронка, rate limit и fallback-метрики.
- [ ] Тестовая публикация в канал и отложенная публикация проходят ровно один раз.
- [ ] После merge production canary подтверждает точный commit.
- [ ] Тест rollback guard отклоняет здоровый, нечитаемый и не совпавший по commit deploy.

## Аварийный режим

Если ломается только генерация коллажей, установить
`COLLECTION_COLLAGE_ENABLED=0`. Если новый Telegram UI нестабилен, установить
`BOT_SAFE_MODE=1`: Rich Messages, Rich drafts, inline Rich media,
ephemeral-ответы и коллажи отключатся, а классические карточки останутся рабочими.
Для возврата установить переключатель в `1`/`0` и перед повторным включением
проверить `/status` и production canary.

## Регрессии 1.19

- [ ] Новый пост → Изменить → текст/теги/обложка/кнопки → Готово; исходный вид и отмена.
- [ ] Сохранение/снятие сохранения, поиск, все фильтры «Мои посты», история и возврат домой.
- [ ] Ссылка во время ввода подводки: Новый пост / Добавить в подборку / Продолжить правку.
- [ ] Замена, перестановка и удаление позиции; старая кнопка не меняет другую позицию.
- [ ] Две сессии меняют разные настройки; конфликт одной настройки даёт понятное восстановление.
- [ ] Частичный поиск повторяет только неудачные источники и сохраняет исходный порядок.
- [ ] Неопределённая отправка требует проверки чата; замена не удаляет старое при сбое нового.
- [ ] /privacy удаляет сохранённые карточки и адресуемые квитанции доставки.

Эти пункты предназначены для реального клиента Telegram. Автоматические проверки
не отмечают их выполненными; результаты конкретного выпуска записываются в отчёт.
