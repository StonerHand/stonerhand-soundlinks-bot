## Локально

Нужны Python 3.10+ и токен из [@BotFather](https://t.me/BotFather).
Для разработки используйте отдельного бота: polling и production webhook
одного токена не должны работать одновременно.

```bash
git clone https://github.com/StonerHand/stonerhand-soundlinks-bot.git
cd stonerhand-soundlinks-bot
python -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev]"
cp .env.example .env
```

В Windows PowerShell активация: `.venv\Scripts\Activate.ps1`;
копирование настроек: `Copy-Item .env.example .env`.

Откройте `.env`, замените `BOT_TOKEN=replace-me` своим токеном, затем выполните:

```bash
python -m music_links_bot
```

Для polling достаточно `BOT_TOKEN`; MusicBrainz и iTunes не требуют ключа.
Ключ Songlink необязателен. Без Redis состояние в памяти не гарантирует
сохранность после перезапуска. Все настройки перечислены в [.env.example](../.env.example).

## Свой канал и inline-режим

1. Добавьте бота администратором своего канала с правом публикации.
2. Укажите `ADMIN_CHAT_ID` и `PUBLISH_CHAT_ID` в окружении.
3. Проверьте часовой пояс `BOT_TIMEZONE` для отложенных постов.
4. В BotFather включите `/setinline` и задайте подсказку
   `Исполнитель — Название или ссылка`.
5. Откройте `/start`, соберите карточку и проверьте чистое превью перед отправкой.

`/settings` сохраняет язык RU / EN, оформление новых карточек и настройки
хэштегов. Настройки не переписывают существующие черновики. `/privacy` показывает
порядок удаления пользовательских данных; `/status` и `/stats` доступны администратору.

## Возможности Telegram 1.20

- **Гостевой вызов.** В настройках бота в Mini App BotFather включите Guest Mode.
  Отправьте в другом чате `@StonerHandBot` вместе со ссылкой либо ответьте этим
  упоминанием на сообщение со ссылкой. Бот вернёт одну карточку; при нескольких
  совпадениях поиска предложит выбрать релиз через inline.
- **Статистика inline.** В BotFather выберите `/setinlinefeedback` → нужного бота
  → `100%`. `/stats` администратора покажет пять самых часто отправляемых карточек
  за текущую неделю по UTC. До включения обратной связи данных нет; при выборке
  меньше 100% счётчик отражает только полученные события. Это не клики по площадкам
  и не прослушивания.
- **Панель релиза.** «О релизе» в обычном сообщении бота в группе открывает личную
  панель поверх карточки. Исходное сообщение остаётся общим. Если Telegram отклонит
  панель, откроется личный чат бота. У inline-сообщения Telegram не передаёт боту
  адрес чата, поэтому его кнопка сразу ведёт в личный чат. Там доступны все площадки
  и копирование названия или ссылки. Копирование названия пропускается, если оно
  превышает лимит Telegram в 256 символов UTF-16.
- **Стоп.** Действует на текущий поиск в личном чате, в том числе между экземплярами
  Vercel при доступном Redis. Уже найденные позиции остаются доступны; общий запрос
  к провайдеру продолжается, если его ожидает другой пользователь.

После обновления повторно вызовите `/api/set_webhook`: он подключит `guest_message`,
`chosen_inline_result` и `stopped_message_generation`, сохранив ожидающие updates.
В основном проекте это автоматически делает Production canary после успешной
проверки нового выпуска; для своей копии настройте адрес и `CRON_SECRET` в workflow.
Polling использует тот же список событий. Переключатели BotFather не включаются
через Bot API автоматически.

Общая панель хранит сведения о релизе и ссылки до 180 дней; после истечения срока
нужно прислать ссылку заново. В общей панели нет личной подводки или настроек
черновика. Подписи результатов inline кэшируются до 48 часов, обезличенные недельные
счётчики — до 31 дня после последнего события. Идентификаторы пользователей,
тексты поисковых запросов и чаты получателей в эту статистику не записываются.

## Vercel и Redis

Подключите репозиторий к проекту Vercel с корнем в каталоге репозитория.
Маршруты и сборка уже описаны в [vercel.json](../vercel.json).

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | Токен рабочего Telegram-бота |
| `TELEGRAM_WEBHOOK_SECRET` | Проверка входящих updates |
| `SET_WEBHOOK_SECRET` | Защита настройки webhook |
| `WEBHOOK_BASE_URL` | Публичный HTTPS-адрес проекта, без пути `/api` |
| `UPSTASH_REDIS_REST_URL` | REST-адрес Upstash Redis |
| `UPSTASH_REDIS_REST_TOKEN` | Токен Redis |
| `CRON_SECRET` | Защита обработчика очереди |

Секреты задаются в окружении платформы. Пример `.env.example` хранится в Git,
рабочий `.env` исключён через `.gitignore`. Старые имена `KV_REST_API_URL` и
`KV_REST_API_TOKEN` поддерживаются для совместимости.

После развёртывания зарегистрируйте webhook через защищённый `/api/set_webhook`.
Он принимает `SET_WEBHOOK_SECRET` в параметре `secret` либо `CRON_SECRET`
в заголовке Authorization. Пример второго варианта из доверенной оболочки
с уже заданными переменными окружения:

```bash
curl --fail-with-body --silent --show-error \
  -H "Authorization: Bearer ${CRON_SECRET}" \
  "${WEBHOOK_BASE_URL}/api/set_webhook"
```

Проверьте `/api/health`: Telegram, webhook и Redis должны быть доступны.

| Маршрут | Назначение |
| --- | --- |
| `/api/telegram` | Входящие updates Telegram с проверкой секрета |
| `/api/set_webhook` | Защищённая настройка webhook, профиля и команд |
| `/api/queue_worker` | Защищённая обработка очереди |
| `/api/health` | Диагностика, версия, commit и состояние очереди; только чтение |
| `/api/smoke` | Контракт публикаций и основных экранов без отправки сообщений |
| `/api/collage` | Совместимость со ссылками на коллажи в старых постах |

### Расписание и выпуск

[queue-worker.yml](../.github/workflows/queue-worker.yml) вызывает обработчик
каждые пять минут. Укажите одинаковый `CRON_SECRET` в Vercel и GitHub Actions;
для своего домена задайте GitHub Actions variable `QUEUE_BASE_URL`. Запустите workflow
вручную и проверьте `last_tick_at` в health. Плановые запуски GitHub могут
задерживаться; время отправки зависит от фактического запуска обработчика.
Ежедневный Vercel Cron служит резервом.

[production-canary.yml](../.github/workflows/production-canary.yml) проверяет
развёрнутый commit, состояние сервиса и контракт публикаций. Для защищённого
автоматического отката нужны GitHub secrets `VERCEL_TOKEN`, `VERCEL_ORG_ID` и
`VERCEL_PROJECT_ID`. При создании своей копии проверьте адреса в workflow и
`CANARY_BASE_URL` в [production_canary.py](../tests/e2e/production_canary.py).

Отдельный [provider-canary.yml](../.github/workflows/provider-canary.yml)
проверяет публичные музыкальные источники каждые шесть часов. Его результат
отделён от решения об откате: сбой провайдера не означает ошибку нового кода.

### Резервные режимы

- `COLLECTION_COLLAGE_ENABLED=0` отключает коллажи и возвращает превью первого релиза.
- `BOT_SAFE_MODE=1` отключает расширенные форматы и сохраняет классические карточки.
- `RICH_MESSAGES_ENABLED`, `RICH_DRAFTS_ENABLED`, `INLINE_RICH_MEDIA_ENABLED`
  и `EPHEMERAL_GROUP_REPLIES` позволяют управлять отдельными возможностями.
- `BRAND_PHOTO_FRAME=0` оставляет исходную обложку без дополнительной рамки.

Из активированного окружения с установленными зависимостями разработки:

```bash
python -m pip check
python tests/check_dependency_pins.py
python -m pyflakes src api tests
python -m ruff check src api tests

python -m bandit -q -r src api -x tests

python -m compileall -q src api tests

python -m coverage report
python -m mypy
```

[CI](../.github/workflows/ci.yml) запускает тесты на Python 3.10–3.12.
Минимальное покрытие с учётом ветвлений — 72%. Проверка Mypy настроена на
четыре модуля; это не полная проверка типов всего проекта.

Проверка рабочего сервиса без отправки сообщений:

```bash
CANARY_BASE_URL=https://your-bot.example \
CANARY_EXPECT_COMMIT=$(git rev-parse HEAD) \
python tests/e2e/production_canary.py
```

Публичные контракты провайдеров: `python tests/e2e/provider_canary.py`.
Проверку с настоящими отправками `tests/e2e/telegram_canary.py --chat-id <ID>`
запускают отдельно в выделенном закрытом чате; подтверждённые тестовые сообщения
удаляются. Порядок визуальной проверки клиентов Telegram —
в [списке проверки релиза](RELEASE_CHECKLIST.ru.md).


### Надёжность доставки и удаления данных

В standalone polling очередь проверяется каждые 30 секунд в том же процессе,
поэтому работает и без Redis до перезапуска. На Vercel используется внешний
worker из раздела выше. Ошибка Redis возвращает HTTP 503, а время последнего
успешного tick не обновляется при неудачной попытке.

Webhook использует состояния processing → delivering → done/uncertain.
Маркер delivering сохраняется перед первой отправкой и живёт семь дней.
После потерянного ответа Telegram update не отправляется заново автоматически;
администратору нужно проверить результат. Ошибки до отправки допускают повтор.
При настроенном, но недоступном Redis webhook не подменяет общую дедупликацию
локальной. Без Redis защита существует только в памяти одного процесса.

Privacy хранит индекс случайных ID пользователя и при удалении также сканирует
legacy-записи, созданные до появления индекса. На большом хранилище такой проход
может занимать заметное время. После удаления на семь дней остаётся техническая
версия состояния без текста, ссылок или имени пользователя: она не позволяет
ранее начатым запросам вернуть удалённые записи. При rolling deployment старые
экземпляры, ещё не поддерживающие эту проверку, необходимо вывести из обслуживания.

Статистика новых событий увеличивается атомарно и не пересчитывает ранее
потерянные события. Runtime latency/circuit-breaker метрики остаются локальными
для экземпляра и помечены `metrics_scope: instance`; это не глобальные показатели.


## Производительность и диагностика 1.21

`BRAND_PHOTO_FRAME` и `BRAND_LABEL` действуют для обычных обложек и коллажей.
`BRAND_LOGO_URL` задаёт дополнительный логотип обычной обложки. Готовые JPEG
хранятся до часа в памяти текущего event loop, максимум 16 изображений размером
не более 3 МиБ каждое. Одновременные запросы одной обложки объединяются;
композиция ограничена двумя параллельными операциями. Неудачная генерация
не кешируется; обычная обложка, отправленная как запасной вариант, не попадает
в кеш брендированного изображения.

Telegram `file_id` хранится до 30 дней в Redis, при его отсутствии — в памяти
экземпляра. Ключ брендированного варианта учитывает исходный URL, подпись,
адрес логотипа и версию рендера. При изменении картинки по тому же URL измените
и URL (например, версию в пути); содержимое удалённого файла не отслеживается.
HTTP-соединения для обложек и совместимого шлюза Telegram переиспользуются в
пределах event loop и закрываются при остановке приложения.

`/stats` владельца показывает p50/p95 по последним 200 измерениям: `lookup`
(полный запрос, включая ожидание кеша), `queue_delay` (задержка от выбранного
времени) и `queue_delivery` (обработка попытки отправки). Это данные текущего
экземпляра, а не глобальная статистика. В технические записи времени не
попадают URL, текст поста или идентификаторы пользователя.

Очередь по-прежнему обрабатывает до трёх задач за tick. GitHub-планировщик
запускает worker примерно раз в пять минут и не гарантирует точное время;
локальный polling проверяет очередь каждые 30 секунд. Просрочка видна в меню
очереди, автоматические повторы безопасных отказов используют существующий
backoff. При неоднозначном результате отправки сначала проверьте канал,
затем подтвердите повтор вручную. После исчерпания попыток задача удаляется
из активной очереди, а владельцу отправляется существующее уведомление.
